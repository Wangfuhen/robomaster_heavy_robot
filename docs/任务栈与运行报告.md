# 任务栈与运行报告

| 项目 | 内容 |
|---|---|
| 依据 | `gimbal.ioc` 的 `FREERTOS.Tasks01` + `Core/Src/freertos.c` |
| 更新时间 | 2026-11-12 |
| 前提 | 当前机器上没有 CubeMX，`.ioc` 已改，`freertos.c` 按 CubeMX 生成格式镜像；重新生成后应一致 |

## 1. 任务与栈

| 任务 | 优先级 | `.ioc` / `osThreadDef` 数值 | 实际字节（×4） | 用途 |
|---|---|---|---|---|
| `crg_test_task` | Normal | 512 | 2 KB | 调试 / 栈报告 |
| `imu_task` | High | 1024 | 4 KB | IMU + AHRS |
| `gimbal_task` | Normal | 1024 | 4 KB | 云台控制 |
| `shoot_task` | Low | 512 | 2 KB | 射击 |
| `usb_task` | Normal | 512 | 2 KB | USB CDC |
| `chassis_data_task` | AboveNormal | 512 | 2 KB | 底盘数据 |

合计 4096 words = **16 KB**；`configTOTAL_HEAP_SIZE = 32768`（32 KB），加 TCB/队列后仍有约 14 KB 余量。

### 单位说明（重要）

`cmsis_os.h` 注释写 `stacksz` 是 **bytes**，但 `osThreadCreate()` 把数值**直接**传给 `xTaskCreate()`，而 FreeRTOS 的 `usStackDepth` 单位是 **words（4 B）**，中间没有除以 4。

所以：

- `.ioc` 和 `osThreadDef` 里的数字是 **words**；
- 实际字节 = 数字 × 4；
- 不要再“按 bytes 修正”把数字除以 4，否则栈会瞬间缩小 4 倍。

## 2. 运行报告

`Core/Src/freertos.c` 的 USER CODE 区里定义：

```c
volatile uint16_t task_stack_high_water_word[6];
volatile uint8_t  task_stack_overflow_flag;
volatile char     task_stack_overflow_name[configMAX_TASK_NAME_LEN];
```

`Task_Report_Update()` 由 `Crg_test_Task` 每 100 ms 调用一次，填入各任务**剩余栈**（单位 words）：

| 下标 | 任务 |
|---|---|
| 0 | `crg_test_task` |
| 1 | `imu_task` |
| 2 | `gimbal_task` |
| 3 | `shoot_task` |
| 4 | `usb_task` |
| 5 | `chassis_data_task` |

查看方式：Keil 调试时把 `task_stack_high_water_word` 加到 Watch，或后续挂到 VOFA。

判读：

- 剩余值 **> 25%** 分配量：安全；
- **10%–25%**：关注，连续多次出现再考虑加栈；
- **< 10%** 或持续下降：必须加栈（改 `.ioc` 后重新生成）。

按“稳定性优先、偶尔零星错误可忽略”的原则：**单次接近阈值不处理；连续多次或单调下降到危险区再处理。**

## 3. 栈溢出保护

`FreeRTOSConfig.h` 已加：

```c
#define configCHECK_FOR_STACK_OVERFLOW 2
```

`freertos.c` 的 USER CODE 区实现了 `vApplicationStackOverflowHook()`：

- 记录 `task_stack_overflow_flag = 1` 和任务名；
- 调用 `NVIC_SystemReset()` 复位。

栈溢出会破坏相邻内存，继续运行不可信，所以这里选择复位；复位后可以在 Watch 里看到 `task_stack_overflow_name`。

## 4. 与 `.ioc` 的一致性

`.ioc` 的 `FREERTOS.Tasks01` 现在是 6 个任务：

```
crg_test_task,0,512
imu_task,2,1024
gimbal_task,0,1024
shoot_task,-2,512
usb_task,0,512
chassis_data_task,1,512
```

`freertos.c` 里：

- 6 个句柄、6 个原型、6 组 `osThreadDef`/`osThreadCreate` 都在生成区；
- `usb_task` / `chassis_data_task` 的 USER CODE 手工创建已移除，改为生成区；
- 两个弱定义 `__weak void Usb_Task` / `Chassis_Data_Task` 也按生成格式补上（强定义在各自 `.c` 里覆盖）。

重新用 CubeMX 打开 `gimbal.ioc` 生成后，任务列表、优先级、栈大小应与当前 `freertos.c` 一致；自定义的报告/溢出钩子都在 USER CODE 区，不会被覆盖。
