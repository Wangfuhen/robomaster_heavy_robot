## 1. 规则

### 1.1 物理量一律带单位后缀

| 物理量 | 后缀 | 示例 |
|---|---|---|
| 角度 | `_radian` | `absolute_angle_radian` |
| 角速度 | `_radian_per_second` | `absolute_angular_velocity_radian_per_second` |
| 长度 | `_millimeter` | `pitch_axis_screw_length_minimum_millimeter` |
| 线速度 | `_millimeter_per_second` | `pitch_axis_screw_speed_millimeter_per_second` |
| 转速 | `_revolution_per_minute` | `rotor_speed_revolution_per_minute` |
| 温度 | `_degree_celsius` | `motor_temperature_degree_celsius` |
| 编码器计数 / 电流指令计数 | `_count` | `encoder_count`、`commanded_torque_current_count` |
| 时间 | `_millisecond` | `last_update_time_millisecond` |
| 力矩 | `_newton_meter` | （预留） |

### 1.2 不使用缩写

`ecd` → `encoder_count`，`rpm` → `revolution_per_minute`，`gyro` → `angular_velocity`，
`temp/temperate` → `temperature_degree_celsius`，`cacl` → `calculate`，`updata` → `update`，
`enconde` → `encoder`，`sen` → `sensitivity`，`cnt` → `count`，`msg` → `message`，
`cfg` → `configuration`，`init` → `initialize`，`max/min` → `maximum/minimum`。

**例外（按专有名词保留）**：`CAN`、`PID`、`LQR`、`IMU`、`USB`、`PWM`、`HAL`、`MCU`、`CPU`、
`DT7`、`M3508`、`C620`、`9025`。HAL / CMSIS / FreeRTOS / BMI088 / IST8310 等第三方代码不改。

### 1.2.1 词性规则：变量用名词，函数用动词

- **结构体、变量、字段、参数**：必须是名词短语，**不允许以动词结尾**。
  禁止 `_set`、`_get`、`_update`、`_calculate`、`_init`、`_send`、`_parse` 等结尾，
  改用 `_setpoint`、`_measurement`、`_command`、`_state`、`_result`、`_data` 这类名词。
- **函数**：名称必须包含动词，采用 `模块_动词宾语` 或 `动词宾语`，例如
  `Gimbal_UpdateFeedback()`、`ParseMotorMeasurementPayload()`、`GetPitchAxisMotorMeasurementPointer()`。
- **例外**：RTOS 任务入口沿用 `xxx_Task`（`Gimbal_Task()`、`Usb_Task()`）以及 `main()`，
  这是框架约定，不算普通函数。

本次据此修掉的例子：

| 旧 | 新 | 原因 |
|---|---|---|
| `gimbal_control_set` | `gimbal_control_state` | 参数以 `_set` 结尾 |
| `ecd_zero_angle_set` | `encoder_zero_count` | 参数以 `_set` 结尾 |
| `gimbal_can_get` | `gimbal_received_data` | 变量以 `_get` 结尾 |
| `gimbal_motor_get`（注释） | `gimbal motor feedback` | 注释里的动词结尾 |
| `CAN_send` / `CAN_point_get`（注释） | `CAN transmit` / `CAN measurement pointers` | 注释里的动词结尾 |

### 1.3 常量不再用 `#define`

新增的 `gimbal_configuration.h` 里：

- 浮点参数用 `static const float`；
- 整数参数（通道、计数、周期）用 `enum`；
- 每个常量都有单位后缀和注释。

`#define` 只保留在第三方头文件，以及尚未迁移的 yaw 参数（见第 6 节）。

### 1.4 分支里不允许出现裸负号

所有方向假设集中到 `gimbal_configuration.h` 的三个 `sign` 常量，控制代码里只允许出现
`... * sign`，不允许 `-pid_calc(...)` 这种写法。

## 2. 符号模型

### 2.1 两个坐标系

- **关节坐标系**：抬头为正角度、正角速度。IMU 的 pitch 角、PC 下发的目标角都在这个系里。
- **电机坐标系**：C620 正电流 → 电机正转。丝杆速度环的目标和反馈都是转子 rpm，在这个系里。

两套坐标之间只有三个方向关系，全部显式定义：

| 常量 | 默认值 | 含义 | 应用位置 |
|---|---|---|---|
| `pitch_axis_motor_rotation_to_joint_angle_sign` | **-1.0f** | 电机正转是否让关节角增大 | 自瞄串级的电流输出 |
| `pitch_axis_inertial_measurement_angular_velocity_sign` | **+1.0f** | IMU 陀螺仪 Y 轴是否与关节正角速度同向 | `Gimbal_UpdateFeedback()` |
| `pitch_axis_screw_stick_direction_sign` | **+1.0f** | 遥控器俯仰杆向上时目标转速取正还是负 | `Gimbal_CalculatePitchScrewSpeedSetpoint()` |

### 2.2 为什么是三个而不是一个

- 丝杆速度环工作在**电机坐标系**：它比较的是“目标 rpm”和“实测 rpm”，中间不经过关节角，
  所以不应该再乘机械换向系数。旧代码里 `PITCH_SCREW_DIR` 就是这一路。
- 自瞄串级工作在**关节坐标系**：外环输出角速度、内环用 IMU 陀螺，最后才把关节电流换成电机电流，
  所以这里需要机械换向。旧代码里的 `-pid_calc(...)` 就是这一路。
- 遥控器杆向是**操作习惯**：与机械安装无关，单独一个系数。

把三者分开，任何一个装反了只改一行，不会连带把另外两路也翻掉。

### 2.3 默认值为什么是 -1 / +1 / +1

这三个默认值**完整复现了改名前的行为**：

- 自瞄：`sign(-1) * pid_calc(...)` ≡ 原来的 `-pid_calc(...)`；
- 丝杆：`* stick_sign(+1)` ≡ 原来的 `* PITCH_SCREW_DIR(+1)`；
- IMU：`imu_sign(+1) * raw` ≡ 原来的直接赋值。

也就是说，烧进去以后手感应当和现在一致。如果实测某个方向反了，只改对应的那一个常量。

### 2.4 标定步骤（架空）

1. `GIMBAL_OPERATING_MODE_ZERO_FORCE`，手动转丝杆：`encoder_count` 变化、`rotor_speed...` 符号正确。
2. 给 +500 电流：电机正转；记录关节是抬头还是低头 → 定 `motor_rotation_to_joint_angle_sign`。
3. 手动抬头：看 `absolute_angle_radian` 增大还是减小；再看 `absolute_angular_velocity_radian_per_second`
   的符号 → 定 `inertial_measurement_angular_velocity_sign`。
4. 遥控器推杆向上：确认希望抬头还是低头 → 定 `screw_stick_direction_sign`。

## 5. 本次顺带修正的行为差异

| 项 | 改前 | 改后 | 影响 |
|---|---|---|---|
| pitch 编码器解绕阈值 | 用 9025 的 32768/65536，对 8192 的 3508 **永不触发** | 4096/8192，正确解绕 | 越过编码器零点不再跳 2π；但丝杆多圈仍需多圈累计（未做） |
| pitch 相对模式 RC 极性 | `-pitch_channel * -sensitivity`（双负号） | 与绝对模式一致：`+pitch_channel * +sensitivity` | 仅影响 ENCONDE 模式；绝对模式（GYRO/AUTO）行为不变 |
| 丝杆速度环设定值 | 存在 `relative_angular_velocity_setpoint_radian_per_second`（单位是 rpm，名不副实） | 新字段 `pitch_axis_screw_target_rotor_speed_revolution_per_minute` | 行为不变，单位正确 |
| 解析有符号量 | `(uint16_t)` 强转 | `(int16_t)` 强转 | ARM 上数值不变，消除实现定义行为 |
| 解析宏 | 宏 | `static` 函数 | 行为不变，可调试 |
| `ABS` 宏 | 定义但未使用 | 删除 | 无 |

**没有改变**：控制环结构、PID/LQR 增益数值、限幅数值、模式切换逻辑、CAN 报文格式。

## 7. 备份与回滚

两个备份目录都在项目根下：

- `backup_naming_20261111_192050`：转 UTF-8 之前的原始 GBK 文件（`gimbal_task.h`、`can_user.h`、`can_user.c`）；
- `backup_naming_20261111_192358`：本次改名前的 7 个文件，另含 `shoot_task.c.before_fix`、`chassis_data_task.c.before_fix`。

回滚单个文件（示例）：

```powershell
Copy-Item -LiteralPath '<项目>\backup_naming_20261111_192358\gimbal_task.h' -Destination '<项目>\balance_application\all_task\gimbal_task.h' -Force
```

注意：`gimbal_task.h` / `can_user.h` / `can_user.c` 已从 GBK 转为 **UTF-8 with BOM**（`gimbal_task.c` 本来就是）。
Keil 5 能正确识别 BOM；如果团队仍要求 GBK，可在最后统一转回。
