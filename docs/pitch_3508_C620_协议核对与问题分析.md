## 0. 结论速览

1. **通信协议不需要改。** 控制帧 `0x1FF` + ID5 + 大端 + ±16384，反馈帧 `0x205` + 字段布局，1 Mbps 位速率，与手册逐条一致。
2. **唯一的前提是电调 ID 必须为 5**，需要现场看绿灯确认。
3. **协议解析已经加固了两处**：有符号解析改为 `int16_t`，解析宏改成两个函数。还剩三处：`DATA[7]` 错误码、反馈超时、总线恢复。
4. **控制层的核心问题仍在**：三种角度语义、指令速率远超执行器、假限幅、GYRO 冻结设定值、两套 pitch 控制器并存。命名和符号已经理顺，但控制结构没有动。

## 1. 链路与代码路径

```
M3508 ──7-Pin── C620(ID5) ──CAN_H/CAN_L── CAN1(PD0/PD1) ── STM32F407
                                   │
            0x1FF (TX, DATA[0..1])  ← CAN_SendPitchAxisTorqueCurrentCommand()
            0x205 (RX)              → MotorMeasurement_ParsePayload()
                                      → gimbal_motor_measurements[3]
```

- 发送：`Gimbal_Task()` 每 1 ms 调 `CAN_SendPitchAxisTorqueCurrentCommand()`。
- 接收：`HAL_CAN_RxFifo0MsgPendingCallback()` 的 `case CAN_MESSAGE_IDENTIFIER_PITCH_AXIS_FEEDBACK`。
- 取用：`GetPitchAxisMotorMeasurementPointer()` 返回 `&gimbal_motor_measurements[3]`。

## 2. C620 协议逐条对照

### 2.1 控制帧

| 项目 | 手册要求 | 代码实现 | 判定 |
|---|---|---|---|
| 标识符 | `0x1FF` 控制 ID 5–8 | `CAN_MESSAGE_IDENTIFIER_PITCH_AXIS_COMMAND` | ✅ |
| 字节位置 | ID5 → DATA[0]、DATA[1] | `data[0]=高 8 位`，`data[1]=低 8 位` | ✅ |
| 字节序 | 高字节在前 | `(pitch_current >> 8) & 0xFF` | ✅ |
| 量程 | −16384~16384 ↔ −20~20 A | 限幅 ±16000 | ✅ 略保守 |
| 帧格式 | 标准帧 / DATA / DLC=8 | `IDE=STD`，`RTR=DATA`，`DLC=0x08` | ✅ |
| 其余字节 | ID6/7/8 对应 DATA[2..7] | 全写 0 | ✅ 总线上没有 6/7/8 |

### 2.2 反馈帧

| 数据域 | 手册含义 | 代码解析（`MotorMeasurement_ParsePayload`） | 判定 |
|---|---|---|---|
| DATA[0..1] | 转子机械角度 0–8191 | `encoder_count`（`uint16_t`） | ✅ |
| DATA[2..3] | 转子转速 rpm，有符号 | `rotor_speed_revolution_per_minute`（`int16_t`） | ✅ 已修 |
| DATA[4..5] | 实际转矩电流，有符号 | `measured_torque_current_count`（`int16_t`） | ✅ 已修 |
| DATA[6] | 电机温度 ℃ | `motor_temperature_degree_celsius` | ✅ |
| DATA[7] | **错误码**（0 正常，1 存储芯片，2 过压，3 三相线未接，4 位置传感器丢失，5 ≥180℃，7 校准失败，8 ≥125℃） | 未解析 | ❌ 仍缺 |

### 2.3 总线与时序

| 项目 | 手册要求 | 代码实现 | 判定 |
|---|---|---|---|
| 位速率 | 1 Mbps | 42 MHz ÷ 3 ÷ (1+10+3) = 1.000 MHz | ✅ |
| 反馈频率 | 默认 1 kHz，可改 | 任务周期 1 ms | ✅ 需确认未被改低 |
| 标识符唯一 | 同总线禁止重复 | 0x201/0x202/0x203（摩擦轮）、0x205（pitch） | ✅ 前提 ID=5 |
| 终端电阻 | 板载 120 Ω 拨码 | 硬件 | ⏳ 待查 |
| CAN/PWM 互斥 | 不允许同时接 | 硬件 | ⏳ 待查 |
| 滤波器 | — | 掩码全 0，接收全部 | ✅ 能收到，可收窄 |

## 3. 协议层还要做的 3 件事

### P1. 确认电调 ID = 5（最高优先级）

手册：绿灯每秒闪 N 次 = ID N。三种确认方式：

1. 看灯：正常状态下绿灯 1 秒内闪 5 次；
2. 用 RoboMaster Assistant 连 PWM 口读 ID；
3. 上电后看 `gimbal_motor_measurements[3].encoder_count` 是否随手动转动丝杆变化。

ID 不是 5 时必须同时改两处：

| ID | 反馈标识符 | `0x1FF` 中的字节 |
|---|---|---|
| 5 | 0x205 | DATA[0..1] |
| 6 | 0x206 | DATA[2..3] |
| 7 | 0x207 | DATA[4..5] |
| 8 | 0x208 | DATA[6..7] |

### P3. 解析 `DATA[7]` 错误码（未做）

`motor_measurement_t` 目前只有 `motor_temperature_degree_celsius`，没有错误码字段。建议增加：

```c
typedef struct {
    uint16_t encoder_count;
    int16_t  rotor_speed_revolution_per_minute;
    int16_t  measured_torque_current_count;
    uint8_t  motor_temperature_degree_celsius;
    uint8_t  controller_error_code;      /* 新增：C620 DATA[7] */
    uint32_t last_update_time_millisecond; /* 新增：反馈时间戳 */
    int16_t  previous_encoder_count;
    int16_t  encoder_count_difference;
    int16_t  revolution_count;
} motor_measurement_t;
```

解析函数末尾补一行 `measurement->controller_error_code = payload[7];`。

在 `Gimbal_CalculateControlOutput()` 入口统一处理：

```c
const motor_measurement_t *measurement =
    gimbal_control_state->pitch_axis_state.motor_measurement_pointer;

if (measurement->controller_error_code != 0 ||
    (HAL_GetTick() - measurement->last_update_time_millisecond) > 20U)
{
    gimbal_control_state->pitch_axis_state.commanded_torque_current_count = 0;
    return;
}
```

错误码 3（三相线未接）、4（位置传感器丢失）、5/8（过温）都会让电调**关闭输出**；不检测的话，现象就是“电机不转、PID 一直积分”。

### P4. 反馈超时（未做）

C620 手册没有规定“停止发送控制帧后电调如何动作”，需要实测。但 MCU 侧应该：**超过 20–50 ms 没收到 0x205 就认为失联，输出清零**，并把云台切到无力或报错。

### P5. 总线健壮性（未做）

- `can.c` 里 `AutoBusOff = DISABLE`：进入 bus-off 后节点不会自动恢复，需要重新 `HAL_CAN_Start`。建议打开，或加“连续发送失败 N 次 → 重新初始化”的看门狗。
- 滤波器掩码全 0：所有帧都进中断，可以接受，但可收窄到 0x200–0x20B 和 0x308。
- `HAL_CAN_AddTxMessage()` 返回值全部被忽略：邮箱满时命令会被静默丢弃，建议加计数用于诊断。

## 4. 控制层问题（命名已理顺，结构未动）

### 4.1 A 类：会导致闭环失效或有安全风险

| 编号 | 问题 | 位置（函数/字段） | 后果 |
|---|---|---|---|
| A1 | **编码器单圈回绕**：解绕阈值已改为 4096/8192，但**多圈累计仍未实现** | `Gimbal_ConvertEncoderCountToPitchRotorAngleRadian()`、`pitch_axis_half_encoder_count_range` | 单圈内正确；丝杆要走多圈，`relative_angle_radian` 仍会周期性回绕，位置不能唯一表示 |
| A2 | **同一“角度”三种语义** | `relative_angle_radian`（转子）、`absolute_angle_radian`（IMU）、`pc_pitch`（PC） | 灵敏度/限幅/零点互相串味，调好一个模式另一个就错 |
| A3 | **指令速率是执行器的 5–19 倍** | `pitch_axis_remote_control_sensitivity_radian_per_count`、`Gimbal_CalculatePitchScrewSpeedSetpoint()` | 设定值永远跑在前面，松手后长时间“追目标”，表现为刹不住、过冲 |
| A4 | **外环限幅形同虚设** | `pitch_axis_absolute_angle_maximum_output_radian_per_second = 300` | 任何 >0.1 rad 的误差都饱和，减速距离+延迟导致过冲 |
| A5 | **GYRO 冻结设定值** | `Gimbal_UpdateControlSetpoint()` 的 ABSOLUTE_ANGLE 分支只更新丝杆目标，不更新 `absolute_angle_setpoint_radian` | 切到自瞄（无目标）时角度跳回进入 GYRO 那一刻；有目标时直接跳到 `pc_pitch` |
| A6 | **符号散落** | 已改为三个 sign 常量，见第 5 节 | ✅ 已修复 |
| A7 | **两套 pitch 控制器并存** | `Gimbal_CalculateControlOutput()`：GYRO 用固定转速开环，AUTO 用老串级 | 同一根轴两种动力学，模式切换必踢 |
| A8 | **模式切换不 bumpless** | `Gimbal_HandleOperatingModeChange()` | 目标角、积分、电流没有全部同步/清零 |

### 4.2 B 类：性能与精度（第二阶段）

| 编号 | 问题 | 量化 | 表现 |
|---|---|---|---|
| B1 | 纯 P 环位置静差 ∝ J | 45° 比 0° 大 **41%** | 高角度定点精度略差 |
| B2 | 内环（电流→角速度）增益 ∝ J | 两端带宽差 **41%** | 一端调稳另一端偏冲/偏闷 |
| B3 | 保持力矩所需电流 ∝ J | 45° 比 0° 多 41% | 通常远未饱和 |
| B4 | 角速度上限由机构决定 | `θ̇max = J·ẋmax` | 自瞄追快速目标必然滞后 |
| B5 | 摩擦/自锁/回程差未知 | 未测 | 小角度抖动、单向精度差 |
| B6 | 延迟 | 1 ms 环 + CAN + 电流环 + 丝杆弹性 | 过冲主要来源 |

### 4.3 C 类：需要拍板的决策

1. pitch 是**位置轴**还是**速度轴**？摇杆给角速度、自瞄给绝对角，两者必须共用坐标并无扰切换。
2. 三套“角度”统一到哪一个？建议统一到 IMU 世界系，丝杆位置只作内部量 `x = f⁻¹(A)`。
3. 编码器模式（LQR）还要不要？不要就删掉，避免误用；要就补多圈。
4. 比赛需要的最大角速度/角加速度/定点精度是多少？这决定 B4 是“可接受”还是“必须改机构”。

## 6. 与 3508 / C620 特性直接相关的 5 个点

### 6.1 C620 只有电流环，没有内部速度环

手册的“调速器”指的是电流（转矩）控制：`±16384 ↔ ±20 A`。**没有**“给 rpm 就稳 rpm”的模式。所以：

- 速度环必须在 STM32 里跑（当前 GYRO 分支就是这样）；
- 测速只能用反馈的 `rotor_speed_revolution_per_minute`（1 kHz 更新）；
- 若通信中断且电调保持最后电流，轴会一直出力——见 P4。

### 6.2 3000 rpm 只用了约 35% 的转速上限

手册性能曲线：M3508 输出轴最高约 **450 rpm**（对应转子约 8640 rpm）。当前
`pitch_axis_screw_target_rotor_speed_revolution_per_minute = 3000` 是**转子** rpm：

- 输出轴 3000/19.2 = **156 rpm**，约为上限的 35%；
- 丝杆速度 `ẋ = L·n_out/60`：L=8 mm 时约 **20.8 mm/s**；满速 450 rpm 时约 **60 mm/s**；
- 角速度 `θ̇ = J·ẋ`：20.8 mm/s 对应 **8.5–12 °/s**；60 mm/s 对应 **25–35 °/s**。

如果实测 12 °/s 不够，先提到 5000–6000 rpm（仍有余量），再考虑导程/减速比。

### 6.3 电流限幅 16000（≈19.5 A）过大

丝杆的力矩放大倍数约为 `2πη/(L·J)`。按 L=8 mm、η=0.4、J≈7–10 rad/m 估算，保持 3 N·m 关节力矩只需要电机输出约 0.1 N·m、约 **0.3 A（约 250 个电流单位）**。

- 正常情况下电流在几百的量级；
- 8000（≈9.8 A）的限幅是保持需求的 30 倍以上；
- 一旦丝杆卡死，19.5 A 会在机构里产生上千牛的力，足以掰弯连杆。

建议把 `pitch_axis_screw_speed_maximum_output_count` 降到“实测起动电流的 2–3 倍”，并加“电流长时间接近限幅 → 判卡死 → 切断”的保护。

### 6.4 反馈频率可配置

手册写默认 1 kHz，可在 Assistant 修改。如果被改成 500 Hz 或更低，1 ms 的环里会重复读到同一帧，速度环的微分项会异常。**用之前确认一次。**

### 6.5 温度保护会“静默关输出”

Assistant 里可开/关温度保护；开启后电机 ≥125 ℃ 时电调关闭输出并亮橙灯（1 秒 1 闪）。现象是“突然没力”，而代码只看到电流变 0。配合 P3 的错误码（8）就能区分“过热”与“控制算错”。

## 9. 故障排查树（“电机不转”）

```
0x205 有反馈？
├─ 无 → ID 不是 5 / 接线 / 电调未上电 / 滤波器（当前全通，可排除）
└─ 有
   ├─ 红灯/橙灯异常？ → 按手册：三相线、传感器、过温、ID 冲突
   ├─ commanded_torque_current_count 恒 0？ → 模式是 ZERO_FORCE / 控制器输出 0 / 限幅
   ├─ 有值但 rotor_speed_revolution_per_minute 不动？
   │   ├─ 电流太小，未越过静摩擦
   │   ├─ 丝杆卡死（机械限位/异物）
   │   └─ 方向反了，顶在限位上
   └─ 转速动但 encoder_count 不变？ → 编码器/7-Pin 线
```
