# 底盘任务栈与运行报告

| 项目 | 内容 |
|---|---|
| 依据 | `25_mini_chassis.ioc` 的 `FREERTOS.Tasks01` + `Core/Src/freertos.c` |
| 更新时间 | 2026-11-12 |
| 前提 | 当前机器没有 CubeMX，`.ioc` 已改，`freertos.c` 按生成格式镜像；重新生成后应一致 |

## 1. 任务与栈

| 任务 | 优先级 | `.ioc` / Buffer 数值（words） | 实际字节（×4） | 用途 |
|---|---|---|---|---|
| `crg_test_task` | BelowNormal | 512 | 2 KB | 调试 / 栈报告 |
| `imu_task` | High | 1024 | 4 KB | IMU + AHRS |
| `gimbal_task` | Normal | 1024 | 4 KB | 云台（底盘板保留） |
| `shoot_task` | Normal | 512 | 2 KB | 射击（底盘板保留） |
| `chassis_task` | AboveNormal | 1024 | 4 KB | 底盘控制 |
| `referee_usart_t` | Normal | 512 | 2 KB | 裁判系统串口 |
| `ui_task` | BelowNormal | 512 | 2 KB | 图传/UI |
| `debug_task` | BelowNormal | 512 | 2 KB | 调试 |

合计 5632 words = **22.5 KB**，全部是静态 `.bss`（`osThreadAttr_t` 的 `stack_mem` 指向 `uint32_t Buffer[N]`），不占 FreeRTOS heap。

### 单位说明

- `.ioc` 里的数字是 **words**；
- `freertos.c` 生成 `uint32_t xxxBuffer[N]`，`stack_size = sizeof(buffer)` 是 **bytes**；
- CMSIS-RTOS v2 在 `osThreadNew` 内部按 `stack_size / sizeof(StackType_t)` 换算成 words，所以 `N` words 与实际分配一致；
- 不要再把数字除以 4，否则栈会缩 4 倍。

这次把原来偏小的任务调大：

| 任务 | 原 words | 现 words |
|---|---|---|
| `crg_test_task` | 256 | 512 |
| `shoot_task` | 256 | 512 |
| `chassis_task` | 512 | 1024 |
| `referee_usart_t` | 128 | 512 |
| `debug_task` | 256 | 512 |

`referee_usart_t` 原来只有 128 words（512 B），加上 FPU 上下文（约 200 B）后余量很小，是这次重点加大的对象。

## 2. 运行报告

`Core/Src/freertos.c` 的 USER CODE 区：

```c
volatile uint16_t chassis_task_stack_high_water_word[8];
volatile uint8_t  chassis_task_stack_overflow_flag;
volatile char     chassis_task_stack_overflow_name[configMAX_TASK_NAME_LEN];
```

`Chassis_Task_Report_Update()` 在 `debug_task.c` 的 `Crg_test_Task` 循环里更新（10 ms 周期）：

| 下标 | 任务 |
|---|---|
| 0 | `crg_test_task` |
| 1 | `imu_task` |
| 2 | `gimbal_task` |
| 3 | `shoot_task` |
| 4 | `chassis_task` |
| 5 | `referee_usart_t` |
| 6 | `ui_task` |
| 7 | `debug_task` |

Keil Watch 里看 `chassis_task_stack_high_water_word`，单位 words（剩余量）。

判读：

- 剩余 **>25%**：安全；
- **10%–25%**：关注，连续多次出现再处理；
- **<10% 或持续下降**：加栈（改 `.ioc` 后重新生成）。

按“稳定性优先、偶尔零星错误可忽略”的原则：单次接近阈值不处理，连续多次或单调下降再动。

## 3. 栈溢出保护

`FreeRTOSConfig.h` 已加：

```c
#define configCHECK_FOR_STACK_OVERFLOW 2
```

`freertos.c` 的 USER CODE 区实现 `vApplicationStackOverflowHook()`：记录任务名后 `NVIC_SystemReset()`。

## 4. 与 `.ioc` 的一致性

`.ioc` 的 `FREERTOS.Tasks01` 已按上表更新；`freertos.c` 的 `uint32_t xxxBuffer[N]` 与 `.ioc` 数字一一对应。

当前机器没有 CubeMX，`freertos.c` 是镜像；用 CubeMX 打开 `25_mini_chassis.ioc` 重新生成后，任务列表/优先级/栈大小应一致。自定义的报告和溢出钩子都在 USER CODE 区，不会被覆盖。

## 5. 注意

- 该工程是 **Static** 任务分配，栈在 `.bss`，不走 24 KB heap；heap 仍保留给队列/USB 等。
- `debug_task` 和 `crg_test_task` 在 `.ioc` 里都指向 `Crg_test_Task`，两个任务跑同一个函数；这是工程原有配置，本次未改。
- 若后续要做命名/单位重构，建议单独一轮，先保证这版栈和报告上车验证。
